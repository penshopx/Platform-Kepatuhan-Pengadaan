### 2. Alur Logika Handler (`artifacts/api-server/src/routes/evaluate.ts`)

```typescript
export async function evaluateRuleHandler(req, res, ctx) {
  const { policyPackCode, policyPackVersion, ruleKeys, context } = req.body;
  
  // 1. Validasi: hanya PUBLISHED pack yang boleh dievaluasi
  const pack = await db.query.policyPacks.findFirst({
    where: and(
      eq(policyPacks.packName, policyPackCode),
      eq(policyPacks.version, policyPackVersion)
    )
  });
  
  if (!pack || pack.status !== 'PUBLISHED') {
    return res.status(404).json({ 
      error: 'Policy pack not found or not PUBLISHED' 
    });
  }

  // 2. Ambil snapshot aturan dari pack (bukan dari business_rules live!)
  const packRules = await db.query.policyPackRules.findMany({
    where: eq(policyPackRules.policyPackId, pack.id)
  });

  // 3. Filter berdasarkan ruleKeys jika disediakan
  const rulesToEvaluate = ruleKeys?.length 
    ? packRules.filter(pr => ruleKeys.includes(pr.businessRule.ruleKey))
    : packRules.filter(pr => pr.isMandatory);

  // 4. Evaluasi setiap aturan
  const results = [];
  for (const packRule of rulesToEvaluate) {
    const result = await evaluateSingleRule(packRule, context, pack);
    results.push(result);
  }

  // 5. Simpan sebagai decision_reference immutable
  const decisionRef = await createDecisionReference({
    entityType: 'EVALUATION_REQUEST',
    entityId: crypto.randomUUID(),
    policyPackId: pack.id,
    policyPackVersion: pack.version,
    evaluationInput: { context, ruleKeys },
    evaluationResult: { results },
    snapshot: buildEvaluationSnapshot(pack, packRules, results)
  });

  return res.json({
    decisionReferenceId: decisionRef.id,
    evaluatedAt: decisionRef.evaluatedAt,
    policyPack: { ... },
    results
  });
}
```

### 3. Keputusan Desain Penting

| Keputusan | Alasan |
|-----------|--------|
| **Hanya baca snapshot, bukan `business_rules` live** | Menjamin reproduktibilitas. Jika aturan berubah, evaluasi historis tetap konsisten. |
| **`decision_reference` dibuat dalam transaksi yang sama** | Tidak boleh ada evaluasi tanpa jejak audit. |
| **`explanation` dihasilkan oleh rule engine, bukan hard-coded** | Penjelasan harus merujuk ke pasal, nilai input, dan kondisi yang cocok secara dinamis. |
| **`overrideApplied` ditampilkan eksplisit** | Auditor harus tahu apakah aturan nasional atau daerah yang dipakai, dan mengapa. |
| **`status` dibedakan: APPLICABLE vs PASSED vs FAILED** | "Tidak berlaku" berbeda dengan "gagal". Keduanya penting untuk kepatuhan. |

### 3. Alur Kerja Verifikasi Hukum

```
1. Admin memasukkan sumber hukum → status: UNVERIFIED
2. Admin menambahkan pasal (raw text dari naskah resmi)
3. Admin hukum meninjau → klik "Verify" → status: VERIFIED
   - Trigger mencatat actor, timestamp, dan alasan verifikasi
4. Admin membuat business rule yang merujuk ke pasal terverifikasi
5. Admin menyusun policy pack dari aturan-aturan tersebut
6. Admin klik "Publish":
   - Sistem cek: semua sumber mengikat harus VERIFIED
   - Jika ada yang UNVERIFIED → tampilkan daftar blokade
   - Jika OK → minta alasan → snapshot → status: PUBLISHED
```
