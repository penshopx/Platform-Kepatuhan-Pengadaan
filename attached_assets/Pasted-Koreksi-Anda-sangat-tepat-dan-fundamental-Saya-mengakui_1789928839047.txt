Koreksi Anda **sangat tepat dan fundamental**. Saya mengakui bahwa saran sebelumnya tentang `BEGIN`/`ROLLBACK` melalui `db.execute()` **tidak akan bekerja** karena masalah connection pooling.

---

## 🔍 ANALISIS MASALAH

### Mengapa `db.execute(sql\`BEGIN\`)` Tidak Bekerja

```typescript
// ❌ SALAH: Ini tidak bekerja seperti yang diharapkan
await db.execute(sql`BEGIN`);
await db.insert(legalSources).values({...}); // Bisa pakai koneksi berbeda!
await db.execute(sql`ROLLBACK`); // ROLLBACK koneksi yang berbeda!
```

**Masalahnya:**
- `db` adalah Drizzle ORM instance yang menggunakan **connection pool**
- Setiap `db.execute()` bisa mengambil koneksi berbeda dari pool
- `BEGIN` di koneksi A, `INSERT` di koneksi B, `ROLLBACK` di koneksi C
- Transaksi tidak bekerja lintas koneksi

### Mengapa Supertest Juga Bermasalah

```typescript
// ❌ SALAH: Request HTTP tidak masuk ke transaksi test
await db.execute(sql`BEGIN`);
const res = await request(app).post('/api/rules/evaluate').send({...});
// Request ini pakai koneksi dari pool yang berbeda, tidak dalam transaksi!
await db.execute(sql`ROLLBACK`);
```

**Masalahnya:**
- API server menggunakan connection pool sendiri
- Request HTTP di-handle oleh koneksi yang berbeda dari test
- Transaksi test tidak mencakup operasi database dari API server

## ✅ SOLUSI YANG BENAR

### Pendekatan 1: Pinjam Client + Dependency Injection

```typescript
import { Pool, PoolClient } from 'pg';
import { drizzle } from 'drizzle-orm/node-postgres';

describe('Policy Engine Tests', () => {
  let pool: Pool;
  let client: PoolClient;
  let testDb: any; // Drizzle instance dengan client tunggal

  beforeAll(() => {
    pool = new Pool({ connectionString: process.env.TEST_DATABASE_URL });
  });

  beforeEach(async () => {
    // Pinjam SATU koneksi dari pool
    client = await pool.connect();
    
    // Mulai transaksi di koneksi ini
    await client.query('BEGIN');
    
    // Buat Drizzle instance yang menggunakan koneksi ini
    testDb = drizzle(client);
    
    // Inject ke API server
    app.set('db', testDb);
  });

  afterEach(async () => {
    // ROLLBACK di koneksi yang sama
    await client.query('ROLLBACK');
    
    // Kembalikan koneksi ke pool
    client.release();
  });

  afterAll(async () => {
    await pool.end();
  });

  it('should create decision reference', async () => {
    // Gunakan testDb yang sudah di-inject
    const [source] = await testDb.insert(legalSources).values({...}).returning();
    
    // Request HTTP sekarang menggunakan testDb yang sama
    const res = await request(app)
      .post('/api/rules/evaluate')
      .set(testAuthHeader(MOCK_ADMIN_USER))
      .send({...});
    
    expect(res.body.decisionReferenceId).toBeDefined();
    
    // afterEach akan ROLLBACK di koneksi yang sama
  });
});
```

**Keuntungan:**
- Semua operasi (test + API server) menggunakan koneksi yang sama
- Transaksi bekerja dengan benar
- ROLLBACK membatalkan semua perubahan

**Tantangan:**
- Perlu mekanisme dependency injection di API server
- API server harus bisa menerima `db` instance dari luar
